# Web管理画面

`/admin`（ローカルでは http://localhost:3000/admin）からClerkでログインします。管理画面へのリンクは公開ページに表示していないため、URLを直接開いてください。

## 操作

1. 配信者名で検索します（空欄で検索すると全員を表示）。
2. 「Steamを登録」または「変更」を押します。
3. 本人のSteamプロフィールの数値ID付きURL、SteamID64、SteamID3を入力し「保存」。
4. ランクは登録直後に取得され、以後約1時間ごとに更新されます。
5. 「解除」→「解除する」で紐付けのみ削除します。配信履歴は残ります。

カスタムURL `/id/名前` は非対応です。`/profiles/数値ID` を使ってください。

配信者一覧と紐付け候補は、画面表示・検索・追加表示の操作時だけ取得します。管理画面を開いたままでも一覧の継続監視や定期取得はしません。配信状態・視聴者数・ランクを最新にするには「更新」を押してください。登録・変更・解除（Steam名検索／マッチIDからの登録を含む）後も一覧を取得し直します。更新時は先頭30件に戻ります。ランク取得は登録後に非同期で進むため、取得結果は「更新」で確認できます。

一覧の時刻は先頭ページの取得時刻です。追加ページは取得時点が異なり、途中でLIVE順が変わると取りこぼしが生じる場合があります。「更新」で先頭から取得し直せます。更新状況パネルは開いている間だけ従来通り自動更新します。

## Steamの名前から登録

1. 「Steamの名前から登録」にプロフィール名を入力し、「アカウントを検索」。
2. アバター・Steam ID・プロフィールのリンクで候補を確認し、「紐付け」。
3. 配信者を検索・選択して「保存」。

検索は管理者限定で、ボタンを押した時のみ実行します。Deadlock APIの `/v1/players/steam-search` を利用し、最大20件を表示します。`min_matches_played_last_30d=0` を指定して活動試合数による絞り込みを解除しています。Steam全体ではなくDeadlock APIが把握しているプロフィールが対象です。同名アカウントは別々の候補として表示されます。

## マッチIDから登録

1. 管理画面上部の「マッチIDから登録」にIDを入力し、「参加者を表示」。
2. 使用ヒーローとSteam表示名を確認し、該当する参加者の「紐付け」を押します。名前のリンクからSteamプロフィールも確認できます。
3. 配信者を検索・選択し、「保存」。既存の紐付けを置き換える場合は「変更して保存」と表示されます。

参加者情報はDeadlock APIの `/v1/matches/{match_id}/metadata`、日本語ヒーロー情報は `/v1/assets/heroes?language=japanese`、Steam表示名は `/v1/players/steam?account_ids=...` から取得します。検索は管理者限定です。表示名は取得時点のプロフィール情報であり、試合当時の名前とは異なる場合があります。

取得できない試合・取得制限・通信失敗は画面に表示します。名前やヒーロー情報のみ取得できない場合はIDを表示します。ボットなど有効なSteam IDのない参加者は登録対象から除外します。保存には既存の登録処理を使い、別の配信者に登録済みのSteamアカウントは重複登録できません。

## 認証設定

Next.jsの `.env.local`（本番ではホスティング先）:

```
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=Clerkの公開キー
CLERK_SECRET_KEY=Clerkの秘密キー
```

Convexの環境変数:

```
CLERK_JWT_ISSUER_DOMAIN=https://your-instance.clerk.accounts.dev
CLERK_ADMIN_USER_IDS=user_管理者のID
```

複数の管理者は `user_one,user_two` のようにカンマで区切ります。空欄では全員アクセス不可です。Clerkでログインできても、このリストにないアカウントは編集できません。管理者IDは認証済みのClerk subjectと照合し、issuerも確認します。メールアドレスやクライアントから渡された権限を信用しません。

現在の開発環境には `convex` JWTテンプレート（claims: `{"aud":"convex"}`）を設定済みです。別のClerk環境を作る場合は、ClerkのConvex integrationを有効化するか、このテンプレートを作成してください。インストール済みConvex SDKはどちらにも対応しています。

ClerkのキーはNext.jsだけで使用し、秘密キーをConvexやブラウザーへ渡しません。認証プロバイダーは管理画面だけで読み込みます。管理用の検索・登録・解除はすべてConvex側で権限を再確認します。

本番へ移す場合は本番用Clerkのキー・issuer・ユーザーIDをそれぞれ指定し、Next.jsとConvexを反映します。開発用のユーザーIDは本番とは別です。

## 動作確認

- 未ログインではログイン画面のみ。
- 一般アカウントでは「管理者権限がありません」。
- 指定した管理者では配信者の一覧、検索、登録・変更・解除。
- 公開ページはログイン不要。

[ClerkとConvexの公式ガイド](https://docs.convex.dev/auth/clerk)

配信者一覧は「Steam未登録のみ」が初期ONです。OFFにすると登録済みも表示します。検索・更新・追加表示でもこの条件を維持し、切り替えると先頭ページに戻ります。登録後は未登録一覧から外れます。ランク未取得・取得不可でもSteam紐付けがあれば登録済みとして扱います。読み取り量を制限するため30件ずつ調べるので、未登録者が少ないページでは表示件数も少なくなります。「さらに表示」で続きへ進めます。紐付け候補のダイアログは登録変更にも使うため全員が対象です。
